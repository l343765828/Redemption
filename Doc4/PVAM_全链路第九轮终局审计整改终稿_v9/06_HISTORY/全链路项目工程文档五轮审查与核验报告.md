### 2.3 B4-01/B4-03 负向注入复现证据

使用套件副本分别注入单一错误，保持其他材料不变：

```text
CASE=report_orphan
注入：REPORT 追加 R-999
RC=0  OUTPUT=TRACEABILITY_V3_PASS core_edges=14 non_core=11 works=9

CASE=task_single_side
注入：仅从 TASK-PVAM-07A 删除 CHK-TEST-001，Manifest/WORK 不变
RC=0  OUTPUT=TRACEABILITY_V3_PASS core_edges=14 non_core=11 works=9

CASE=status_mismatch
注入：Manifest 中首个 RISK 的 UAT_VERIFY 改为 ACCEPTED
RC=0  OUTPUT=TRACEABILITY_V3_PASS core_edges=14 non_core=11 works=9
```

校验器的关键实际逻辑为：

```python
# 精确集合差只覆盖 WORK 节点
for wid, w in works.items():
    compare_sets(..., w['steps'], agg[wid]['steps'])
    compare_sets(..., w['tests'], agg[wid]['tests'])
    compare_sets(..., w['evidences'], agg[wid]['evidences'])

# 上游边仅做跨文档字符串存在判断
if token not in task_text + work_text + report + mod:
    fail(...)
```

因此，官方 `selftest_traceability_v3.sh` 的正/负例退出 0 只能证明其覆盖的 WORK TC/EV 和父子错误可被拦截，不能证明跨五层双向闭包。

## 3. 审核总结论

### 【REJECTED】

本套件尚未达到“文档治理 APPROVED / APPROVED_FOR_CONSTRUCTION（可正式开工）”准入标准，不能从上一轮 `REJECTED` 升格。

### 3.1 决策依据

1. **仍有阻断性机器追溯错误。** B4-01 声称的跨五层双向校验未实现；可复现的 REPORT 孤儿和 TASK 单侧断边均被错误放行。
2. **Manifest v3 并非全覆盖。** `TC-020` 在 PLAN/TASK 中存在却未进入任何 `controlled_test_mappings`，且非核心状态未按域强约束；这是结构错误，不是微观笔误。
3. **活动控制身份仍自相矛盾。** 实际只有 `validate_traceability_v2.py`；PLAN、REPORT、WORK 总方案仍把 `.v2` 文件称作机器事实源，而该 `.v2.json` 内容又是 schema 3。WORK 总方案的 R-012A/B CHK 边仍是旧集合。单一事实源未成立。
4. **状态解耦未闭合。** WORK-08 的证据合同测试仍使用无域 `status=BLOCKED`，与自身 `STATUS_SCHEMA.md` 冲突。
5. **组织授权明确未满足。** 当前是 `DRAFT/PENDING_ORGANIZATIONAL_APPROVAL/BLOCKED`；没有批准人、签名、范围与允许 Wave。即使内部技术缺陷全部修复，也不能在该门禁未签署时正式开工。
6. **真实代码/DEV/UAT 从未被本包证明完成。** REPORT 的代码结论仍为 `REJECTED`；真实 WORK commit/patch、DEV 证据、UAT 证据和生产回滚清单均未生成或签署；DEC-013 与 Gate C 继续 `OPEN`。

### 5.2 `trunc_div_zero` 最小复现

WORK-01 当前设计片段为：

```python
def trunc_div_zero(numerator: int, denominator: int) -> int:
    if denominator == 0:
        raise ZeroDivisionError("denominator must not be zero")
    quotient = abs(numerator) // abs(denominator)
    return -quotient if (numerator < 0) ^ (denominator < 0) else quotient
```

沙箱结果：`3/2=1`、`3/-2=-1`、`-3/2=-1`、`-3/-2=1`、`1/-2=0`、`-1/2=0`、`0/-2=0`，零分母抛 `ZeroDivisionError`。裁决为 `CONFIRMED`（设计函数四象限正确）。固定基线尚无 `Common/PvAmount.py`，不得写成“代码已修复”。
