主服务（处理与缓冲）
1. 接收 Kafka 订单消息

2. 【状态检查与防并发锁】
   读取 Redis 中的状态 (order_id:status)
   - 若状态为 `MQ_SENT`：说明彻底成功过，直接 Return ACK。
   - 若状态为 `PROCESSING`：说明有其他线程或重试正在处理，抛出异常，让 Kafka 稍后重试。
   - 若不存在：使用 SETNX 写入状态为 `PROCESSING`，并设置过期时间（例如 1 分钟，防止死锁）。

3. 【执行核心逻辑】
   计算返利数据。

4. 【强同步发送 Kafka 落库消息】(关键调整)
   发送落库消息到新的 Kafka Topic。
   !! 必须等待 Kafka Broker 返回确认 (acks=all) !!
   - 若发送失败：抛出异常。Kafka 消费者会重试。（等 Redis 的 PROCESSING 过期后，下一次重试就能进来了）。

5. 【更新 Redis 业务数据并流转状态】
   将返利结果写入 Redis（供你当前服务读取）。
   并将 Redis 里的状态从 `PROCESSING` 改为 `MQ_SENT`（最好用 Lua 脚本保证原子性）。
   - 若此步写 Redis 失败：抛出异常触发重试。（重试会导致第 4 步发两次消息，但 DB 有唯一约束，没关系）。

6. 【提交 Offset】
   手动或由框架 ACK，确认消费完成。

异步落库服务
1. 消费【异步落库消息】
2. 开启 MySQL 事务
3. 尝试插入返利数据 (依赖 order_id 唯一索引)
   - 若报 DuplicateKeyException (唯一冲突)：说明是重试导致的重复消息，忽略错误，直接认为成功。
   - 若是其他数据库异常：回滚事务，抛出异常，等待落库服务自己的 Kafka 重试。
4. 更新订单状态为“已返利”
5. 提交事务，ACK 消费完成。
